# Project instructions

- Canonical checkout: `/Users/zjz/code/noir-poker`. Edit `src/` and `index.html`; never hand-edit generated `dist/`.
- Make each new change on a dedicated branch and open a GitHub pull request. Do not push changes directly to GitHub `main` or merge a pull request without the user's instruction. Keep any earlier unpublished changes in the same proposed branch when requested.
- Target `main` by default. Include required unpublished dependencies in the proposed branch instead of targeting another feature branch, unless the user explicitly requests stacked PRs. For stacked PRs, provide and maintain a final integration PR into `main`; a merged child PR is not delivery to `main`. Before reporting complete integration, fetch the remote and verify every delivered source commit is reachable from `origin/main` (or document verified equivalent changes), and check local commits and worktree edits for unpublished work.
- Preserve no-login local practice, virtual chips and Chinese UI. Keep the existing Sites project ID in `.openai/hosting.json`.
- Rules live in `src/engine/poker.js`. Do not duplicate settlement or legal-action logic in UI. Small blinds must be positive multiples of 25; the chip denomination equals the small blind and starting stacks equal 100 big blinds. Changing blinds resets the entire game, stacks and statistics. Blind amounts, starting stacks and chip denomination come from the per-game configuration (defaults 100/200, 20000 and 100). Every wager, call, stack, pot, refund and award must use whole chips of that game’s denomination, including odd-chip splits. Never hard-code the starting stakes into rules, bot thresholds or review. Any rule change needs a boundary regression test and chip-conservation verification.
- BTN's next clockwise seat is SB, then BB. Short all-ins, raise reopening, eligibility and uncalled refunds must retain existing semantics.
- Review uses before-action public snapshots. Never use hidden opponent cards, future deck or final winners to grade a decision. Distinguish estimates, heuristics and proven rule errors.
- Timer/Worker changes must preserve cancellation on next hand, retry and reset. Retry restores original deal and retracts payouts/statistics exactly once.
- For UI changes, resolve and verify Web first, then validate the native apps and WeChat mini-program. Update the corresponding E2E and unit regressions in the same change.
- Validate material changes with `npm run check`; UI changes with `npm run test:e2e`. Use `npm run format:check` before delivering. E2E fixtures run only in Vite test mode and must never enter production.
- Fully localize all new user-facing player research in every supported Web/App locale, including identities, formats, facts, observations, adaptations, limitations, source labels and source context. Preserve dates, amounts, cards, attribution and evidence limits accurately. Include structured research in extraction and validation; do not bypass translations with `translate="no"` or Chinese-only research blocks. Original URLs, stable IDs and official proper names remain intact.
- If changing paths or commands, update README and docs in the same change. Do not store publishing credentials in this repository.
- Web and native apps share `src/` and `index.html`. Native releases must bundle local assets; do not add a production `server.url` or remote code-update mechanism. Keep Xcode/Gradle hooks that rebuild the latest Web source, the source/copy verification, and background cancellation semantics.
- Native build scripts and configuration changes require `npm run mobile:sync` and `npm run mobile:verify`; actual Xcode/Gradle compilation must be reported separately from browser or resource checks. Keep signing material and generated native Web copies out of Git. Follow `docs/mobile.md` and `docs/mobile-release.md` for version and release operations.
- WeChat shares `src/engine/`, `src/review/` and local portrait sources. Keep its `src/platform/wechat-controller.js` and `miniprogram/` native interface in sync when changing gameplay or settings. Never hand-edit `.artifacts/wechat/`. `npm run dev` watches the shared source; `npm run build` regenerates the mini-program. Run `wechat:verify`, `wechat:check` and adapter regressions for changes; report compiler/mock checks separately from WeChat DevTools or device tests.
- Every native release must retain and verify local image assets. Run installed iOS/Android App E2E on actual simulators/emulators in addition to compilation, and retain reports/screenshots. Never report a configured suite, resource check or browser test as a native runtime pass.
