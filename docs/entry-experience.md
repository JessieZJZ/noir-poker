# 入座体验与音乐渐入

Web、iOS、Android 和微信使用同一套入座顺序：启动图结束后显示未发牌的牌桌，同时按保存的声音选择从头播放本地音乐。牌桌中央显示「牌桌已就绪」和「入座开练」，顶部显示「等待入座，即将开始第 x 局第 x 手」。不显示“第一手”说明。

局数和手数由对局记录的 `nextHandIdentity` 只读预览提供，与真正创建记录时复用同一个新局判定。预览不会创建牌局、扣除盲注、移动筹码或改变统计。继续原局时显示保存进度的下一手；设置在开练前变更人数或盲注时，预览会反映即将建立的新局。

待入座时收起操作栏占用的高度，让「本局练习」上移，隐藏空的「本局动态」。点击开练后才调用现有规则引擎发牌、扣盲注和开始记录。所有端共享 1300 ms 的发牌展示等待，覆盖九人桌最后一张底牌的 1260 ms 动画。动画期间不能行动，不启动电脑思考或玩家回合提醒；之后恢复原有行动节奏。

发牌等待在真正切后台时保留剩余时长，恢复前台后继续。换手、重打、重置和页面销毁取消旧回调，不能由上一段等待推进新的牌局。历史结算页会移除入座元素及待入座样式，不会展示开练按钮。

音乐在实际开始播放后执行 2400 ms 的平滑渐入。音频被手势策略阻止或尚在加载时不消耗渐入，也不提前推进媒体播放。前后台和声音开关保留播放位置，恢复时使用 700 ms 渐入；换手、重打、重置、设置和记录页不会重建音乐播放器。微信动作期间的降音量与渐入相乘，动作结束不会跳过入场渐入。浏览器仍遵循自动播放限制，需要手势的环境会在首次真实操作时从头渐入。App 沿用本地容器允许自动媒体播放的现有配置，不加载远程音乐。

顶部设置入口为无圆形边框的 19 px 齿轮及「设置」文字，保留 44 px 点击高度。字号、字重和垂直对齐跟随右侧较小的文字；「玩法指南／对局记录」轮播及菜单行为保留。

## 验证

```sh
npm run check
npm run test:e2e
npm run i18n:check
npm run format:check
npm run mobile:ios
npm run mobile:android:qa
npm run mobile:sync
npm run mobile:verify
npm run wechat:verify
npm run wechat:check
```

Web 入座用例覆盖所有 5–9 人桌、零下注和筹码守恒、重复点击、动画完成前禁止行动、前后台、继续原局以及音乐实际解码和渐入。测试模式关闭 HMR，避免同目录的开发改动在交互断言期间重新加载页面；生产构建仍不包含测试夹具。

安装版专项名为 `entry-waiting-music-and-first-deal`，验证首次原生触摸前音乐已在播放、待入座状态、顶部设置与文字、收起空操作区、真实点击入座及后台恢复。源码资源检查、Xcode/Gradle 编译和安装运行分别记录，不能互相代替。

微信实际 DevTools 专项：

```sh
node tests/wechat/entry-experience.mjs ws://127.0.0.1:9466 .artifacts/entry-experience/wechat-runtime
```

端口替换为实际自动化端口。该专项观察真实 `InnerAudioContext`，保留待入座截图，覆盖所有等待人数及继续原局编号，并保存、恢复本地测试前的设置和对局记录。生命周期部分调用真实 App 处理器，与实体微信客户端切后台和实体手机听感分别报告。

iOS 重启专项在应用停止期间释放旧的 Web Inspector／驱动会话，再以不重装、不清数据的方式连接并激活应用，避免旧检查连接阻塞新页面启动。静音等偏好仍由真实应用重启验证。

本轮通过项、失败重试及验收边界见[验收记录](entry-experience-validation-2026-10-20.md)。
