## 修改内容

- 行动提示间距在响应式尺寸变化时会被挤压。下注快捷按钮原有的 `transition: 0.2s` 同时过渡字号、内边距等几何属性，短暂增高按钮行并将滑条向上推。原始失败测得下方间距 3.34375px，诊断还捕获到 2.4375px。改为仅过渡颜色，并将紧凑提示位置设为 2.5px；保留原有 4px 最小间距、上下差不超过 1px 的断言，增加无几何属性过渡检查。
- 长按提示测试原本采样循环滚动的当前位置，位置回到零时会误报。改为观察真实 DOM 滚动事件，仍验证无关滚动不能关闭提示、牌桌滚动必须关闭提示。没有停止轮播。
- 原生验收服务仅加载当前平台驱动，避免 iOS 启动服务时额外加载 Android 驱动而超时。Android 保留限定在自身驱动的 WebView 下载权限。
- iOS 验收先独立安装、启动应用，等待本次 PID 的原生首屏确认，再启动本任务 Appium 服务和 XCUITest 会话。保留 45 秒要求；旧 PID 或仅有 JavaScript `ready` 的日志不能放行。正常首启没有额外 JavaScript 查询或提前移除封面。
- 增加本地网页启动阶段、原始错误，以及 Debug 原生导航日志，区分平台设置、语言、样式、牌桌与封面确认。原生消息处理器保留弱引用，避免从隐私页返回时新文档引用已移除的处理器；重复确认不重复移除封面。
- 高盲注原生布局用例原先修改持久化配置后未恢复，导致后续默认盲注断言收到 10K/20K。现于 `finally` 恢复原配置，并在原生重启后断言一致，保留两种盲注的原有断言。
- 微信复盘验收从实际风格配置读取名称，避免写死更名前的标签；仍要求角色与实际配置名称同时匹配。

## iOS 启动对照

遵守“不操作其他任务，等待机器空闲”的要求，没有暂停、终止或关闭其他任务、设备和预览窗口，只清理本任务明确拥有的进程与设备。

V3 冷启动尝试失败于 `independent-startup`，本任务 Appium 尚未启动，实际执行 0 个牌局场景。启动前连续三次 CPU 空闲约 25%–32%，模拟器启动后负载再度升高；原生日志停在导航进度 0.3，尚未进入网页初始化。系统日志显示本地入口已经交给 WebKit，但导航未完成。GPU 断开连接发生在测试超时后的系统关停阶段，不能据此判断 GPU 崩溃。

随后预先启动同一专用设备并保留主屏幕，独立首屏正常完成，报告记录约 8009ms，之后才启动本任务验收服务。第一轮继续运行发现高盲注用例串扰，已修正。修正后重跑通过 29 项，包括音乐、设置持久化、盲注排队与筹码守恒、结算复盘、重打、后台取消、5–9 人牌桌对照、次级页对照和历史返回；最后的记录重打与恢复场景按用户要求中止。

这组对照证明该安装包能够正常首启和运行，不能据此宣称已完全排除宿主负载影响，也不能把预启动设备的通过替代模拟器冷启动稳定性或实体设备验收。原始失败 `ios-final-v3/`、串扰失败 `ios-warm-final-v3/` 与中止记录全部保留。早先含临时 JavaScript 查询的诊断不计为正常首启验收，临时查询已移除。

Android 更早的失败发生在应用安装之前：系统服务 ANR、未达到 `boot_completed=1`，日志同时包含 API 36 要求 GLES 3.1、host 路径仅提供 GLES 3.0 的警告及显著 CPU/I/O 压力。它们是集成复验需控制的因素，尚无本轮 Android 安装运行结果，不能认定唯一根因或报告已恢复。
