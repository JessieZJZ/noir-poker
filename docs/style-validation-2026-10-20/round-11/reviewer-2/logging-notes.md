# 日志说明与自误更正（不修改既有理由）

interaction-raw.jsonl 逐行保存每个 POST 前 GET /state 的完整原始 JSON、POST 路径和参数、先行填写的 action/reason、decisionTime、HTTP status 与完整原始 JSON 响应。脚本仅负责请求、显示和 done 后同码下一手；没有牌力判断、默认行动、范围表或策略。

时间字段：time 是 GET 发起前时间，decisionTime 是 GET 返回后且 POST 发起前保存时间，responseTime 是底层 req() 在 POST 发起前捕获的时间，名称不够准确，应解释为 POST 发起时间，不能当作接收结束时间推算网络耗时。没有事后改写旧理由。

A67/A68运输进程超过最初默认10秒的即时输出窗口，随后只 GET 核对已经推进到A68/A69，没有重发动作，原进程仍完成原始响应落盘。A93/A96/A99等超时使用原会话等待。所有后续POST前state与上一行响应经JSON比较完全相同。初次空state连通检查和两次超时恢复GET的工具输出未独立纳入该POST日志，其状态在邻接POST行中保留。

H的API手号是全局101–200，码内顺序1–100。开始H101后发现全局编号，修改运输上限为各码已start次数100即停；这只是计数控制，不依据牌、胜负、对手行动筛选。没有跳局/重抽。

自误与表达限制：A21河牌理由出现“多人常见Q或花仍胜”，实际该决策是Hero与A单挑，“多人”是措辞误用，原始state显示只有两人，未更改旧理由。H162跟入理由说“避免无位置大池”，实际Hero在CO相对UTG与盲注有位置、相对BTN无位置，应理解为避免后方继续时放大，并不能说CO全程无位置。H128转牌Q高花听的跟注用了高张和隐含赔率补足直接赔率，这是主观边缘判断，结算发现目标更高花不能追溯改成当时已知。Hero打法有位置与同花性的手动权衡和边缘混合，未经GTO校准，不是最优策略证明。

done阶段结算后只检验stack和，不重复加显示的残留pot。未结束时检验stack+pot。所有共街和施压统计为事后公开行动统计，不用于决定API动作。
