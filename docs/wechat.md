# 微信小程序工程

手机在 `app.json` 和牌桌页面默认声明 `pageOrientation: portrait`，保持竖屏；启用 `resizable: true`，允许 iPad 和大屏客户端旋转、调整窗口。牌桌、记录列表、记录详情和资料来源页通过 `page-meta` 统一应用方向策略：按设备完整屏幕的短边识别平板（至少 600 逻辑像素，或 iPad 型号），平板使用 `auto`，手机使用 `portrait`；不依据键盘弹出或分屏后的临时窗口大小改变设备分类。方向变化只重算布局，不重新发牌或关闭当前弹窗。相关声明及 `onResize` 状态保留有单元回归；编译器和适配器检查不能代替微信开发者工具或实际平板验收。配置依据：[微信大屏适配指南](https://developers.weixin.qq.com/miniprogram/dev/framework/view/resizable.html)、[page-meta](https://developers.weixin.qq.com/miniprogram/dev/component/page-meta.html)。

牌桌和记录列表还读取渲染视口，并监听实际宽度变化；尺寸事件比同步窗口接口优先，以兼容开发工具旋转后仍返回旧尺寸的情况。离开页面时断开监听，返回后重新测量；键盘或滚动造成的同宽高度变化仍不重新分配牌桌空间。开发工具更新模板后可能保留旧服务层脚本，验收前应只清理目标工程的编译缓存、重新打开并核对构建摘要，不能把旧脚本运行结果归给新产物。

小程序只使用简体中文，没有语言设置，产物不包含国际化代码与语言资源。Web/App 的多语言功能独立保留。小程序使用本地 WXML/WXSS 界面，直接复用 `src/engine/`、`src/review/` 和风格插画源文件。主界面不加载在线网站，也没有账号或网络牌局；风格介绍不再提供人物资料或来源网页入口。规则、筹码、电脑风格与复盘计算只有一份实现；界面与生命周期由 `src/platform/wechat-controller.js` 和 `miniprogram/` 适配。

## 每次 Web 迭代如何同步

`npm run dev` 同时运行 Vite 和小程序监听器。保存 `src/`、`public/`、`miniprogram/`、`scripts/`、`mobile/` 或构建配置后，小程序重新生成到同一个导入目录；开发者工具读取更新后的文件。单独监听可运行 `npm run wechat:watch`。`npm run build` 的 `postbuild` 也自动生成小程序，`npm run platforms:sync` 一次同步小程序与 iOS/Android 最新资源。

微信开发者工具里的“编译”只编译已导入的 `.artifacts/wechat`，不会执行仓库的源码生成步骤。只修改 `src/` 或 `miniprogram/` 而未重新生成，该按钮仍会读取旧版本。多工作目录并行开发时，监听器必须从当前工程对应的 checkout 启动；另一个 worktree 的监听器不会更新此目录。暂停测试验收时仍可单独生成预览资源，不需要运行 E2E。若重建后工具仍显示旧文件，只清理该工程的编译缓存并重新打开，保留存储与本机 IDE 偏好。

每次生成都从当前共享源码转译 CommonJS/ES2019，把引用的 JSON 数据内嵌到 JavaScript 模块，保留共享 JavaScript 模块之间的引用，压缩生成模块的空白、语法与局部标识符以控制包体，保留公共导出与属性名，压缩并裁切全部本地头像，生成本地声音，写入文件清单和源码 SHA-256。小程序运行时无需 Node 的 JSON 模块加载器。`wechat:verify` 拒绝过期源码、损坏文件、缺失头像或不一致的 AppID。主包与每个分包分别采用 2 MiB 的保守预算，总包预算 20 MiB。音乐在本地 `music` 分包，声音开启时通过 `require.async` 加载本地资源入口后用独立循环上下文播放；不占用主包预算，也不使用远程音频 URL。清单记录各包大小，超出就阻止构建。

`miniprogram/project.config.json` 与 `project.private.config.json` 是本机 IDE 状态，忽略 Git 跟踪及模板源码指纹；项目配置由构建器生成，私有偏好从目标工程保留，不进入运行文件清单。调整 IDE 偏好不会让共享源码或运行资源被误判为过期。

生成器从 App、页面、分包和 Worker 的 JavaScript 入口追踪本地 `require` 与 `require.async`，清理没有被引用的 `shared/` 模块，不修改 Web 或原生 App 仍在使用的源文件。发现计算出来的动态模块路径时保留整个共享目录，避免误删。构建回归验证异步、传递和 Worker 依赖仍存在，并确认商店测试配置与旧 UI 下注尺寸兼容模块没有误入包。运行中的牌手说明、头像署名、字体、启动图和音频资源保留。

共享规则、策略、复盘、筹码尺度和头像的修改自动进入小程序产物。Web 的 DOM/CSS 与小程序的 WXML/WXSS 使用不同控件；新增界面特性时需要同步维护小程序适配，不能直接把任意网页 CSS 转成微信控件。项目 AGENTS.md 已加入同步维护与验证要求。

已经发布的微信版本需要重新上传、审核与发布才能更新用户客户端。本地自动生成不等于自动发布；与手机 App 一样，不绕过平台版本分发机制。

## 当前能力与验证

支持 5–9 人、25 面额筹码、最小/半池/底池/全下、电脑思考、下一手、同手重打、公开信息复盘、对手行动筛选、摊牌最佳五张牌和奖励明细、底池明细、本手动态、风格与情绪自动保存、声音开关及提示横幅。公共牌保留五个固定位置，牌区本身的中心对齐桌面中心，筹码和明细不参与居中计算；优先五张单排，空间不足时按 3+2 两排的整体牌区居中。手机采用 Web 的逻辑尺寸和完整玩家占位，先求无碰撞布局，再按可用牌桌整体缩放：公共牌逻辑宽 62–70px，宽度不超过 360px 时为 66px，长宽比为 1.44；英雄牌为 61–72×88–104px。中等竖屏平板使用 106×152.64px 公共牌，大竖屏平板使用 94×135.36px。大竖屏平板放大玩家名称、筹码、风格标签、提示与操作文字；玩家卡片与风格标签保留四侧内边距。筹码放在你的位置标签右侧，最近行动放在最下行；对手行动紧贴玩家块，牌型随后显示。移除重复回合标签，保留底部操作提示；可用与禁用按钮采用明显不同的颜色。弃牌或结算时操作区收为带内边距的一排，牌桌高度始终按行动期间的预算保留，不随按钮变化；设置和详情在全屏弹窗内滚动，背景覆盖整个系统区域与底部安全区，首页保持可滚动。人数、情绪和风格使用紧邻原控件展开的深色下拉选项；新设备默认打开声音，显式关闭后保留选择。弃牌后尚未发出的公共牌可通过“立刻发完”预览，复用规则引擎的练习补牌，不改动实际牌面、牌堆、结算或复盘证据。

真正进入应用后台或卸载练习页会取消旧电脑行动与复盘任务，并释放声音上下文。返回前台重新调度当前牌局，不执行离开前的过期回调。导航到对局记录或历史结算页时，实时控制器由 App 保留，当前游戏继续正常进行；历史页另用只读快照控制器，不能改变实时筹码或统计。

界面迭代先完成 Web 修复并运行完整单元/E2E 检查，再执行原生构建与安装运行测试，最后执行小程序生成、模板编译及适配器回归。测试报告按浏览器、模拟器/仿真器、小程序编译/mock、DevTools/真机分别记录。

所有选择控件使用原位置展开的深色列表；次级页面打开时锁定首页滚动，关闭后恢复原位置。首页的重打徽章与提示说明对齐 Web。音效进入时预加载并默认开启，已保存的关闭设置仍保留。

风格介绍直接展示共享的入池选择、翻牌与转牌、河牌取舍、特色操作和应对思路。均衡保留文字头像，其余使用十六张本地成熟插画。牌桌、规则与复盘仍全部使用本地代码。

风格选择卡片顶部对齐；桌上头像跨风格和筹码两行，逻辑尺寸与 Web/App 共用。风格详情按五个标题分段展示，不包含人物经历、赛事资料或引用编号。新手指南直接由 index.html 转换，含九种五张牌示例与 BTN/SB/BB/UTG/MP/LJ/HJ/CO 缩写。

加注原生滑杆采用 28px 滑块和 28px 交互高度，touchstart 立即响应行动状态与音频解锁；changing 只更新加注文字，change 才向共享控制器提交当前筹码面额的合法数值，拖动过程中不回写滑块受控值或重绘桌面。下注／跟注筹码动画为三枚、520ms、60ms 错开，发牌与翻牌沿用 Web 的 600ms／650ms 和 140ms 错开；快速发完刷新每街的结束边界，不播放思考等待。后台、换手与重打使旧动画测量回调失效。

音效由共享 `src/ui/sound-cues.js` 生成确定性 44.1kHz、16-bit PCM：Web/App 用 AudioBuffer 播放，小程序构建同样的 WAV，包括过牌双敲、弃牌下滑、跟注／下注、发牌与结算。对每个 WAV 的每个采样值做相等检查，避免小程序另写频率／包络。弃牌与下注相对原 Web 增益提高约 5.1dB／4.1dB；发牌和结算保留原 Web 音符与时点。快速发完只播最终结算，普通每街播发牌；重打、下一手、重开与重新启用音效播发牌。App 启动即尝试加载并渐入本地音乐分包，保留已保存的静音偏好；入座点击先解锁音频，再播放完整发牌提示，不必等到首次弃牌或跟注。短音效启用微信官方建议的 WebAudio 底层驱动，音乐继续使用适合长音频的普通上下文；参见[官方接口类型说明](https://github.com/wechat-miniprogram/api-typings/blob/master/types/wx/lib.wx.api.d.ts)。过牌双敲保留 240ms 完整播放窗口，随后只接最新一条提示；后台、静音、换手和重打取消未播放的提示，不积压回放旧声音。平台阻止播放时仍需有效用户手势重试，资源或扬声器的实际出声须真机另验。

轮到你行动时，共享回合去重器只通知一次。小程序调用 `wx.vibrateShort({ type: light })`；更新设置、牌面、滑杆或后台恢复不重复提示同一决策。DevTools 的 API 调用检查与真机震感分开记录。

“音效与音乐”统一控制本地循环背景音乐和操作音效；“振动”独立控制行动提醒。新设备均默认开启，各自保存。旧版组合静音会保留为两项关闭，之后可分别调整。音乐由 App 持有，打开设置或浏览记录不重播，真正切后台暂停、回前台恢复，迟到的分包或就绪回调不能在静音/后台重新播放。发牌／翻牌动画作用于整张牌外层，包括白色牌面；英雄牌 600ms、420ms 起始延迟与 130ms 错开，对手牌背 600ms、座位 65ms／牌张 140ms 错开，公共牌及亮牌 650ms／140ms，查看底牌容器另有 180ms 淡入。底牌翻转全程保留静止位置的垂直偏移，结束移除动画标记时牌面不下跳；DevTools 回归分别测量 720ms 和 950ms 的首张底牌坐标。亮牌只更新发生变化的叶子字段，保留其余座位文案、牌型偏移及英雄牌节点。有限动画结束移除标记；换手、重打、后台和卸载取消旧清理回调，避免旧计时器影响新牌局。

## 对局记录

顶部设置按钮与菜单的布局间隔为 4px，菜单宽度为 88px，文字与齿轮视觉距离保持在 12px 内；设置按钮仍为 34px。两种轮换文案使用同一固定文字窗口，切换时不改变间距。

历史详情与实时牌桌共用 `pages/table/table-surface.wxml`；活动模板放在 `table-templates.wxml`。应用启动封面仅存在于实时页入口 `table.wxml`，历史入口不包含它，避免初始数据到达前闪现封面。滑轨触摸由 `raise-rail.wxs` 在渲染层处理，逻辑层只接收金额预览和最终选择，见 [加注滑轨](raise-slider.md)。

顶部菜单提供玩法指南和对局记录，菜单关闭时轮换文字。`pages/records/records` 按局倒序、局内按手和重打次数正序展示图形底牌、输赢、净变化及“补码”标记；局项不显示完成手数。`pages/history/history` 是独立的历史结算页面，复用 `pages/table/page-definition.js` 的结算视图与复盘，只允许查看。关闭后继续同局下一手，未完成手的所有下注撤回、不计统计；待生效人数或盲注变化才会开启新局。更多统计口径见 [本机对局记录](game-records.md)。

## 行动提醒

Web、App 与小程序共用 `src/ui/hero-turn.js` 的提醒状态，以及 `src/styles/hero-turn.css` 的动效。小程序构建将样式复制为本地 WXSS；修改这份共享源文件后重新构建即可。手牌移除背光及包住两张牌的大框，每张牌沿自身圆角和倾斜轮廓显示薄荷绿细边框，复用对手“思考中”的 `turn-glow` 动画与 2 秒柔光节奏。边框位于卡牌伪元素上，独立于发牌动画，卡牌和按钮不移动；玩家等待行动期间持续循环，调节下注也不中断。操作区顶部使用两束 2px 细光，以 1.6 秒周期分别从中心向左右移动并消退，宽度保持不变，不再缩放整条线，也不添加光晕。行动提示使用统一的常规字重和颜色，以逗号连接，例如“轮到你行动，跟注需要 200 筹码。”，保持常亮，不呼吸或发光。控制器原有入场、等待和单次补提醒状态继续保留，手牌边框在这些状态下保持同样节奏；调节下注会取消本次补提醒，保留行动提示。后台全部停止，返回后恢复等待提示；行动结束时清除提示。减少动态效果时保留静态边框及细线；原有振动与声音偏好继续有效，视觉提示不依赖声音开关。

首屏在收到完整座位与两张本人底牌的同次更新前展示透明图标启动层，牌桌与导航一起显示，避免先露出指南标题。图标从共享 `public/launch-icon.png` 生成 128px 本地 PNG。系统级微信启动页由微信客户端管理，仓库控制的是小程序自己的首屏。

历史详情初次进入直接展示结算终态，不触发底牌、公共牌或牌背的入场动画，也不为只读页面分配音效池；手动点开某位对手的底牌仍保留该次翻牌动效。

复盘保留 600 次权益抽样与默认 40 次候选行动模拟。5–7 张牌直接按点数计数和花色掩码求最佳五张，输出与原子集算法一致；无听牌时不扫描无效补牌，已有特征不重复推导。复盘逐决策展示已完成结果，整手统计等全部完成后再生成；后台、重打、换手、关闭仍取消旧 Worker，缓存仅保存已完成的决策。

`tests/wechat/device-experience.mjs` 只允许在独立复制、无用户牌谱的 `touristappid` 工程运行；它会练习一手自然牌局，检查实际音乐／音效事件、原生滑杆尺寸和历史详情终态。先在该副本内以 `NOIR_WECHAT_APP_ID=touristappid node scripts/wechat.mjs build` 构建，再连接该副本自己的自动化端口，例如 `node tests/wechat/device-experience.mjs ws://127.0.0.1:9492 .artifacts/device-experience`。该检查不能证明扬声器听感或实体手机拖动表现，不得为测试清空真实 AppID 的记录，也不要复用其他任务的开发工程。

## 牌组两列布局验收

先构建并校验当前源码，等 DevTools 页面就绪后运行 `node tests/wechat/matchup-columns.mjs ws://127.0.0.1:9498 .artifacts/matchup-columns/wechat`，端口替换为本次工程的自动化端口。脚本临时展示外部公开快照生成的翻前、翻牌和河牌牌组，检查本人／对手视角的每行两个布局，保存实际位置、设备尺寸和截图，结束后还原页面字段及弹层。它不修改牌谱或在生产包内加入测试入口，也不代表实战策略或真机验收。
