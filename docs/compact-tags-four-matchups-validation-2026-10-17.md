# 对手位置标识、查看底牌与四类输牌示例

## 行为

移动布局中，对手位置标识缩小，眼睛按钮放大；英雄位置标识和普通桌面布局维持原尺寸。Web、Native 和微信共用 `compactTableLayout` 的尺寸参数。下表为布局缩放前的 CSS 尺寸：

| 布局     | 对手位置字号    | 眼睛按钮宽高 |
| -------- | --------------- | ------------ |
| 手机     | 14px；短屏 15px | 20px         |
| 竖屏平板 | 14px            | 24px         |
| 大竖屏   | 17px            | 26px         |

眼睛继续只在结算后显示，仍通过原按钮查看、收起底牌。微信覆盖原有不同布局的按钮尺寸规则，保持与 Web/App 一致。

翻后“当前会输的可能牌组”最多展示四组。案例中直接把三改四仍会得到“顺子、三条、葫芦、踢脚更高的两对”，同花仍排在后面。因此同样两对仅踢脚更高的示例会让位于不同的更强成牌类型，案例现在显示“顺子、三条、葫芦、同花”。不同对子点数构成的更强两对仍正常参与选择。四组为示例上限，不表示所有可能牌组均已列出。

未修改牌型比较、坚果证明、公开范围权重、机器人决策或筹码规则。翻前可能牌组和当前能赢牌组的原有数量规则不变。

## 回归案例

`paired-flush-review.js` 用合法的九人桌合成行动还原截图中的 A♣4♣、7♠J♦A♠10♣J♠、26.6K 底池及需补 13.6K 的价格，Hero 在 SB、Theo 在 HJ。它不声称恢复了截图之外的实际历史。

测试分别让实际对手持弱牌和 K♠Q♠，结算赢家不同，但行动前公开信息和输牌示例完全一致。每个示例都重新验证牌型比较、已知牌阻断和合法底牌，同时检查总筹码 180K；只有两张同花色的河牌面不生成同花示例。

Web E2E 覆盖 320–1032px、5/9 人桌、全部对手的标识/眼睛尺寸及排列，并用真实按钮切换底牌。普通桌面维持 17px 位置字号和 20px 眼睛。截图等待有限动画结束。
