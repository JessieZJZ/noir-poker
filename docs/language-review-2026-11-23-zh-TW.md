# 繁体中文（台湾）全目录语言审校（2026-11-23）

本次是十个 locale 并行审校中的繁中（`zh-TW`）一组，工作分支 `claude/lang-review-zh-tw-e2b051`，基线为 `claude/tutorial-ui-optimization-a134c2`（PR #70）的 `b689575`。只修改 `src/i18n/locales/zh-TW.json` 与 `src/i18n/overrides.json` 的 `"zh-TW"` 区块；没有改动其他 locale、`messages.json`、简中源文案或代码。

> **说明：这是 AI 辅助审校，不是台湾母语使用者的人工签核。** 用语判断参照台湾常见的扑克与软件用语，仍建议由台湾玩家实际试玩后再确认，尤其是下文“未改与存疑”中列出的术语。

## 范围与方法

- 逐条审阅 `messages.json` 的全部 2,359 条源文案在繁中的**生效值**（locale 文件与 override 合并后，override 优先）。键在 override 中的，就改 override；否则改 locale 文件。
- 覆盖设置、牌桌与动作、日志、玩法指南、牌型、记录、复盘与教练段落、角色与研究资料、错误信息、商店与隐私文案。
- 复盘中的片段与 `{n}` 模板，改写前在 `src/review/`、`src/ui/` 中核对拼接方式；同一句的渐进片段（如“其中至少 {0}…”“同时有 {0} 张…，下一张约”系列）按同一措辞同步修改。所有占位符保留，`npm run i18n:check` 确认无缺失、无占位符变化。
- 数字、金额、牌面、位置（BTN/SB/BB/UTG…）、姓名、日期、出处与证据限定均未改动；短标签保持原长度或更短（“下手生效”为消除歧义改为“下一手生效”，多一字）。
- 字形限制：所有新增汉字都已在 `public/fonts/coverage.json` 内。审校中“金融卡”“客服”“涵蓋”三处用到了子集外的字（融、客、涵），已改用“付款資料”“支援”“包含”。

## 未改与存疑

- **保留的既有决定**：功能名“覆盤”（PR70 用户选择）、“補碼”、“決賽圈”。本应用只有一张牌桌，“決賽桌”会让人以为要换桌，且 `pr70-locales-zh-fr-ru` 的回归仍固定“決賽圈不可補碼”。
- **沿用但可再讨论的术语**：取值、暗三條、踢腳、跛入、平跟、冷跟、領打（donk）、隱含收益、四條（台湾口语也说“鐵支”）、莊位。这些在台湾扑克圈都能理解，但不同社群用词不一，建议人工确认。
- “檢視”与“查看”两种说法并存，台湾两者都常用，未强行统一；指南标题“怎樣贏下一手”等保留“怎樣”。
- “預設棄牌／預設跟注”在此指“预先认定”，台湾也有此用法，保留。
- 独立片段键 `封口` 只在句子缺少整句翻译时作为短语替换兜底，保留原词；两处整句中的“封口”已改写为“本輪下注尚未結束”“後面已無人能再加注”。
- 1,310 个 locale 旧键与 126 个 override 旧键不在 `messages.json` 中，不对应当前源文案；另有 124 个 locale 值被同名 override 遮盖、不会生效。这些本次都未改。
- 字形子集限制下，“金融卡”“客服”“涵蓋”无法使用，分别改用“付款資料”“支援”“包含”；若以后重新生成字体子集，可再考虑。

## 源文案问题（未修改源文）

- `src/review/matchups.js` 中 `这张 ${cardText(s.board)} 是多人底池…` 及同一函数的 `这张 {0} 较干燥…`：用“这张”指整组公共牌，不通顺。繁中已改为“{0} 這個牌面…”；建议源文改为“这个牌面”或“{0} 这个牌面”。
- `{0} 带{1}，这次可被匹配的新增投入最多 {2} 是当时底池的 {3} 倍…`：`{2}` 与“是”之间缺逗号。
- `src/ui/opponents-controller.js` 的 `下手生效`：简中也可能被读成“动手生效”，建议改为“下一手生效”。
- 源文同时用“埋牌”和“慢打”指同一打法，建议统一。
- “可被匹配的新增投入”“改善候选／补牌候选”在简中也偏术语化，可考虑“对手跟得起的新增投入”“可改善的牌”。
- “脏牌”在简中也不常见，可考虑“杂牌”。
