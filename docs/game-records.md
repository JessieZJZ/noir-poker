# 本机对局记录

Web、原生 App 与微信小程序都使用 `src/engine/game-records.js` 保存局、手和每次重打。无需登录，不上传记录；各浏览器和应用的数据彼此独立。

## 页面与排列

顶部原“玩法指南”改为轮流显示“玩法指南 / 对局记录”的下拉入口，菜单固定提供两个选项。自动切换以 400ms 从上到下滚动，文字区域尺寸不变；下拉与局折叠箭头不带圆圈，对局记录的局项与手项箭头垂直居中。打开菜单、悬停、聚焦或开启减少动态效果时不轮换。

对局记录是独立页面。局按开始时间倒序，局内最新一手在最上面，同一手的重打也按最近一次在前排列。微信首次显示最新 24 条，加载更多时追加更早的记录；存储与统计仍保留原始时间顺序。所有局默认展开，点局标题可折叠；返回列表保留折叠状态和滚动位置。局项显示局号、时间、胜率、净筹码变化、起始大小盲和牌桌人数，不显示已完成手数。手项展示图形化底牌、手号、结果与净变化；首次不显示额外文案，重打用有颜色的“重打1／重打2”标签，自己的补码后首手标“补码”。局和手的净筹码变化始终带正负号，零为 `+0`，输掉但筹码没变时为 `-0`，沿用当前的完整数字或 K/M 显示设置。已结算手都有输赢：零筹码变化时依引擎是否获得底池显示“赢”或“输”，不显示“持平”。

点击已完成手进入独立历史结算页，展示当次结算牌桌、分池与未跟注退回、本局动态及复盘。历史与实时牌桌共用卡牌、玩家信息、牌型和行动的渲染及布局，同一手、同一视口下位置与尺寸一致。它不能下一手、重打、重置或修改筹码；结算后的看牌只修改此历史页的展示。当前牌桌显示第几局、第几手。浏览记录不暂停机器人，返回游戏看到实时最新状态；真正切到系统后台仍遵循原有取消、恢复计时规则。

Web/App 的详情不另放“底池结算”卡片；点击牌桌“明细”查看所选历史手的底池、边池及退款弹窗。若该手有摊牌，牌桌下方展示 Showdown 与每人的最佳五张牌，与微信一致；无摊牌不显示。弹窗与摊牌模块只读取所选存档，不随当前练习更新。

打开详情时静态展示已公开的底牌；点击“查看底牌”时，仅该玩家的两张牌沿用实时牌桌的翻牌动效，收起后再次查看可重播。其他玩家和公共牌保持静态；减少动态效果设置仍生效，看牌不改变历史快照或当前游戏。

详情页顶部显示“本地练习”，与“返回游戏”按钮居中对齐，下面显示所选尝试的开始时间（完整年月日和时分）。删除上方重复的局／手标题和浏览提示，牌桌顶栏保留局号、手号与重打标签，移除“本手结束”及其前面的分隔符；实时牌桌的阶段文案不变。为辅助技术保留不可见的页面标题。每局开始时间也包含年份；Web/App 按当前语言和设备时区显示日期，切换语言或刷新不修改原始开始时间。每次重打使用该次尝试已保存的独立开始时间，不把浏览时间当成开始时间。

系统回退按详情→列表→游戏返回；“返回游戏”一次退出本次记录浏览，重新打开不会嵌套另一套列表。Web/App 使用独立 URL 和受管理的浏览历史，iOS 支持边缘回退手势，Android 返回键先关闭弹窗和菜单、再回退记录页面；微信使用独立原生页面及同一存活的牌桌页。

实时和历史牌桌使用相同的稳定视口预算。滚动和手机浏览器工具栏展开、收起不会改变桌高；真实宽度或方向变化才重新布局。牌桌文案适度放大，窄矮的 9 人手机屏仍优先首屏同时容纳牌桌与操作。人物标签使用固定行高，包括韩文，长名称省略展示。被截断的姓名或风格标签可长按／长点击，在附近查看完整名称；弹层避让屏幕边缘，点击空白处、滚动或离开页面后收起。

玩家信息的内边距检查以实际文字和头像、位置、看牌按钮的边界为准，不能仅检查 CSS 的 padding 值；自己的位置标签也保留上下和左右内边距。筹码数字保留完整精度。没有看牌图标时，姓名使用释放的空间，少数溢出的姓名按实际字体宽度轻度横向适配；有看牌图标或极长姓名时允许省略号，完整身份数据不变。

公共牌优先一排，并与牌桌两端和玩家保留间距；一排过小时比较两排后的实际牌面大小，两排明显更清晰且不会过度压缩整桌时才切换。底牌与公共牌保持接近的比例，多人桌允许缩小底牌以留出邻座间距。行数、桌高、座位和操作预算不随发牌或结算变化，同时检查旋转后的牌面与邻座、底池、公共牌的间距。手机、平板和桌面窗口分别限制底牌增长，避免把手机放大幅度直接用于 PC。

自己的底牌下面没有牌型或获胜标签时，身份、筹码与行动两行靠近牌面；出现标签时留出标签的间距。两种状态共用固定的英雄区域预算，不因标签出现或消失重新改变桌高、牌面或操作区位置，历史结算页也使用相同规则。

练习统计标题为“本局练习”，不再显示旁边的“本次牌桌”标签。音效由 Web/App 和微信共用同一组本地 PCM 生成，弃牌、过牌、筹码、发牌和获胜音统一提高响度，并限制峰值与叠加失真。保留用户静音设置、首次真实操作解锁及后台停止，不修改设备的系统媒体音量；程序响度与实体手机室内听感分别验收。

## 局与统计

普通下一手和补码继续同一局。重新练习结束旧局并开启新局。人数、盲注变更排队到新手开始时才结束旧局、按新配置重置整桌并开启新局；改回当前设置则取消排队。显示、语言、难度或风格设置不单独重置局，沿用既有生效时机。

所有已结算尝试保留。开始重打时，原尝试的结算从整局统计撤回；重打完成后只计入新的结果。列表不显示“已被重打替代”标签，历史结算页也不显示“历史记录”标签；牌桌自身保留与实时结算一致的重打标记。重打过程中关闭，也不会重新计入已被替代的尝试。正在打和未完成的行没有输赢或净变化，不参与统计。

获胜率沿用引擎“获得底池”的口径，分池也计获胜。赢得部分底池但整手净亏损时明确显示“获得部分底池 · 净亏损”。净变化按结算退款与奖池收入减本手投入计算；补码是投入，不能记为盈利。重打从引擎原始手状态恢复，不重新发牌或重复补码。

## 关闭、刷新与筹码恢复

每次发牌后立即持久化本次尝试、自己的底牌和恢复点，无需依赖关闭事件。恢复点包含补码完成后、盲注扣除前的所有座位筹码、尝试前统计、手号和庄家；不包含原始发牌或未来牌堆。

关闭或刷新后，把上一条尚未结算的尝试标“未完成”，恢复所有人的本手投入，保留补码成本一次，然后从同一局下一手继续。手号递增、庄家轮转，不恢复旧牌堆。已完成结算则从结算后筹码和统计继续。若有排队的人数或盲注变更，在这个新手开始时正常开启新局。

历史结算快照包含当次结算所需底牌、公共牌、分池、动态及复盘记录，但移除未来牌堆。复盘评分仍只使用原本的行动前公开快照；结算与后来公开回应不会反过来评价之前的决策。历史复盘独立于实时复盘，即使当前手结算也不会覆盖历史输入。

索引键为 `noir-game-records-v1`（数据版本 2），只保存局、手的摘要与恢复基线；每手完整快照单独存放：Web 与原生 WebView 使用 IndexedDB `noir-records`（首屏前载入内存），微信使用用户目录 `noir-records/` 下每手一个文件。不读取其他格式的记录；格式不符时开始新的记录并只提示一次。快照上限 Web/原生 4000 万字符、微信 6000 万字符；超出时先删除最早结束的局，再删除当前局最早的手，正在记录的手不会删除，清理不提示。损坏或不兼容的索引不能进入规则引擎，与索引不符的快照只是不能打开。读取或保存失败只以轻提示弹出一次，不在页面常驻，重启后不再沿用。

局标签：进行中的当前局为“进行中”；决出名次的局为“冠军”或“第x名”；因改设置或重新练习结束、没有名次的局不加标签。清除浏览器站点数据、应用数据或卸载应用会移除本机记录。

## 记录列表的性能边界

列表使用缓存的 `summaries()`，不读取或复制结算快照。`revision()` 只在记录变化时失效；Web/App 的实时行动刷新和微信的一秒轮询在记录未变时跳过列表构建。完整快照只在打开某一手时由 `getAttempt()` 读取；原有完整 `sessions()` 只保留给诊断和测试使用。记录仍按原格式完整保存，不丢弃旧局、旧手或复盘材料。

微信只给展开的局生成手牌视图，每次先展示 20 局、每个展开局先展示 24 手，底部按钮继续加载；折叠局只传标题和统计。牌面图片样式按牌缓存，只传列表真正使用的字段，已存在的行使用字段补丁，新增行按索引追加。首次显示、加载更多局或新局插入导致重排时，都先传小标题，再按每批 24 手分批传入各局手牌，避免把全部历史及牌面放进一个 `setData`。Web/App 同样延后生成折叠局的手牌节点。

微信记录页左侧为“对局记录”，右侧为宽度随文字变化的“返回游戏”，移除重复宣传标题；详情页的时间下方间距为 8px，历史复盘操作区为 58px，实时练习仍使用原先的操作区预算，牌桌与座位布局不变。

检查详情见 [记录页性能与间距验证](records-performance-validation-2026-10-15.md)。

对手亮出的两张牌在各端使用更大的牌面，下沿藏在信息卡片之后，整体宽度小于信息卡片；扩大可见牌面不改变座位占位或整桌缩放，顶部可覆盖教学提示。
