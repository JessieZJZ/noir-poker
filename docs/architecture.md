# 架构与状态流

## 一次行动如何发生

1. `index.html` 加载 `src/main.js`，引入样式和 `table-controller.js`。
2. 牌桌按钮调用 `heroAction()`，引擎通过 `legalActions()` 和 `act()` 校验轮次、金额、加注权及筹码。
3. `act()` 在修改状态之前记录玩家决策快照，包含公开风格、情绪类别和行动权状态。对手隐藏底牌、剩余牌堆和未来结果不会进入玩家快照。
4. `render()` 根据引擎状态刷新筹码、牌面、位置、操作和动态；`schedule()` 安排对手行动或下一轮发牌。
5. 轮次进入 `between` 后，`advanceStreet()` 发公共牌，或者触发 `settle()`。
6. 结算按每个池的参与资格比较最佳五张牌，并支付、退还和更新统计；重复结算受到保护。
7. 摊牌控制器显示每位未弃牌玩家的成牌，复盘控制器保存本手的独立输入。玩家分析与对手执行解释各自使用隔离的数据。

`game` 是牌桌控制器持有的唯一进行中状态。规则计算位于纯引擎模块，不在按钮中重复实现。各模块在同一个浏览器内运行，不依赖登录、服务端或数据库。

下注快捷项的金额均为本轮累计“加注至”，不是这次新增投入。`engine/bet-sizing.js` 供界面、机器人和复盘共用：先假定补齐跟注，再以跟注后的底池计算加注增量，`currentBet + roundChips(fraction × (pot + callAmount))`。最小筹码为 25，比例金额按最近 25 档位取整，恰好半枚时向上；最后使用引擎提供的合法最小／最大额裁切。无人下注时就是按当前底池下注。引擎在行动记录及支付前拒绝非法金额，结算按整枚 25 筹码分配平手余数，确保余额、底池与退款仍为 25 的倍数。最小、全下及短全下仍完全使用 `legalActions()` 的边界，不修改加注权。

每位玩家的 `lastAction` 保存已执行动作的公开文案、发生轮次及当时累计下注。同一下注轮内，最近行动在角色下方保留，直到新的真实行动替换；发出公共牌进入下一轮时，普通下注、加注、跟注、过牌及盲注文字从牌桌清除，全下和弃牌继续显示，原全下金额不丢失。`visibleRecentAction()` 仅按轮次过滤显示，不删除记录；结算后再次展示每位玩家最后一次真实行动。当前轮次的 `action`、`bet` 仍按规则清理，跟注金额是本次补入，加注和全下金额是动作发生时该轮累计投入。退还未被跟注筹码不会改写原动作，赢家领取筹码也不会把已全下改成其他动作。开始新手清空快照并记录新盲注；重打恢复原手盲注后、尚未行动的基线。查看底牌和练习补牌均不会改写快照。

## 本地选项与新练习

首次进入默认 6 人、标准难度、均衡对手、轻微情绪模拟、开启提示和声音。`ui/preferences.js` 校验并恢复 `noir-table-v1` 中的人数和难度，在第一手发牌前建立对应人数的新桌；选择人数时立即保存意向，本桌仍在下一手切换。

对手配置继续使用 `noir-opponents-v1`，保留所有八个席位及情绪强度；减少人数不会删除暂未入座的风格。声音和提示继续使用 `noir-sound`、`noir-hints`，兼容既有选择。风格需点击保存，关闭未保存的对话框会舍弃草稿。

声音在首次真实触摸、点击或键盘操作时创建或恢复 AudioContext；解锁前跳过音效，避免补播积压的发牌、下注声音。已保存的关闭选择仍保持关闭；恢复失败不会打断牌局。

玩家及机器人正常行动时，弃牌使用 260→75 Hz 的短促下滑音，与下注的单音、发牌的双音和获胜的三音分开。静音开关控制所有音效；“立刻发完”不逐次播放被跳过的机器人行动。

结算时 `ui/settlement-layout.js` 按各座位的真实内容高度（底牌、人物资料、牌型、最近行动）计算所需桌高。相邻座位保留间距、底部状态留在牌桌内；查看／收起底牌、换手、窗口宽度和字体变化时重新测量，不靠透明或裁切隐藏遮挡。

完整刷新或再次进入会恢复选项并开启新练习；底牌、公共牌、筹码、历史、统计和私有执行记录不会存入浏览器。重新练习保留选项；重打仍使用原手基线。损坏、无效或不可访问的存储回退默认值，无法写入存储时本次仍可正常操作。偏好只属于当前浏览器和站点来源，本地预览与在线站点各自保存。

## 异步任务的边界

对手计时器和“立刻发完”持有当前 `epoch`。普通行动先生成私有不透明计划和按局势计算的截止时间；再次安排同一轮保留原计划／截止时间。引擎的 WeakMap 计划校验游戏身份、局次、重打次数、街数、行动者、历史长度、难度及下注状态，防止旧决定写入新局。下一手、重打或重置清空待定计划并递增 `epoch`，旧任务在继续之前核对编号。修改难度重新安排当前机器人的计划。

“立刻发完”取消原定时器，立即消费仍有效的待定决定，再沿同一个合法执行入口完成剩余行动；不等待合成思考时间，也不重新抽第一步决定。不直接生成结算或修改赢家，途中重置仍能取消后续步骤。

复盘优先使用 Web Worker，不阻塞牌桌操作。任务有独立编号；换手或重打终止旧 Worker，过期结果不会写入新手。无法创建 Worker 时按决策逐步计算，使用较少抽样，并在界面显示实际抽样次数。

## 三种“再来一次”

| 操作       | 底牌 / 公共牌序列    | 筹码和统计                             | 位置           |
| ---------- | -------------------- | -------------------------------------- | -------------- |
| 下一手     | 重新洗牌发牌         | 保留练习累计；破产玩家自动补充虚拟筹码 | 庄位顺时针移动 |
| 重打这手牌 | 恢复同一副牌的原序列 | 撤销本手旧结果，恢复本手开始时状态     | 保持原位置     |
| 重新练习   | 新练习               | 重置练习累计                           | 从新桌开始     |

重打基线由引擎保存为独立快照；连续重打不能叠加支付。电脑决策仍会重新运行，因此不同选择可能产生不同跟注或弃牌，不保证获得更多筹码。

## 页面与状态的观察

`window.noir.getState()` 提供公开牌桌状态，供本地诊断和浏览器工具读取。进行中不会返回对手隐藏底牌；摊牌自动公开未弃牌玩家。结算后眼睛按钮只切换对应座位的底牌显示，公开状态与牌桌显示一致。显示偏好不会改变引擎、筹码、统计或复盘输入；下一手、重打和重新练习都会清除它。

结算后的结果以座位皇冠、摊牌牌型对比和底池明细展示，不再添加独立“谁获胜”卡片或按钮上方的重复结果条。行动状态条只在进行中显示，下一手或重打恢复。摊牌详情沿用本局动态的姓名格式：已分配人物风格时显示“Luna（Peter）”，均衡与玩家本人保留普通姓名；名称取本手实际配置，保存的下一手配置不会改写本手。

结算牌桌的公共牌区域与玩家本人区域使用同一纵向文档流，公共牌说明与底牌之间留出 24px 间距。牌型皇冠、最近行动和长姓名增加内容高度时，牌桌会扩展，不再把底牌顶到公共牌说明上。对手座位仍相对牌桌定位，进行中的布局不受结算布局影响。

`document.modelContext` 可用时会注册读取牌桌、执行玩家行动、下一手和同手重打工具。执行工具与点击按钮共用合法性检查。

## 测试环境

`vite --mode test` 的开发插件把 `tests/fixtures/table-fixtures.js` 注入牌桌控制器，提供可控的河牌、多人全下与分池场景。插件只在测试开发服务生效，生产构建没有 `window.qa` 或强制发牌入口。测试场景仍调用真实引擎、渲染和事件处理。

`dist/` 由构建生成，不提交到源码仓库。源码、配置、测试和文档才是迭代入口。

本局动态按事件发生顺序展示：开始、盲注、行动、各轮公共牌、结算。引擎保留最新在前的日志数组，牌桌渲染时复制并倒序显示，避免修改重打基线或其他引擎状态。单列从上到下，多列先读完左列再读右列，连续编号标明时间顺序；屏幕宽度变化和反复渲染不会改变事件顺序。

## 策略与反事实模拟

正常计时行动通过 `planBotTurn()` 取得 `botDecision()` 的返回值与实际随机分支，再按 `botThinkingTime()` 的时长等待；`executeBotTurn()` 执行同一个决定，合法调用 `act()`，只记录一次已执行行为。即时封装 `playBotTurn()` 共用计划／执行入口，“立刻发完”的第一步可消费原待定计划。单纯查询策略或取消未执行计划不写记录。本人底牌、判断扰动、范围门槛、分支抽样、尺度和思考因素只保留于私有游戏状态，结算前不能进入公开诊断接口或复盘输入。重打基线包含空记录，重打会撤销上一尝试的轨迹。

`counterfactual.js` 根据玩家行动前的公开快照创建独立游戏，抽样未知牌；每个候选行动共享同一手抽样牌与后续策略种子。模拟用 `act()`、`advanceStreet()`、`botDecision()` 打完并结算，从而保留短全下、行动权、边池和退还规则。原游戏不被修改。后续判断为快速小样本均衡／公开风格策略，结论只在这些模型内成立，不能被称为 GTO。

Worker 只收到玩家决策与结算展示字段；私有对手执行记录仅用于独立的对手面板，不能进入玩家的模型计算。
