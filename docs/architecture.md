# 架构与状态流

## 一次行动如何发生

1. `index.html` 加载 `src/main.js`，引入样式和 `table-controller.js`。
2. 牌桌按钮调用 `heroAction()`，引擎通过 `legalActions()` 和 `act()` 校验轮次、金额、加注权及筹码。
3. `act()` 在修改状态之前记录玩家决策快照。隐藏底牌、剩余牌堆和未来结果不会进入快照。
4. `render()` 根据引擎状态刷新筹码、牌面、位置、操作和动态；`schedule()` 安排对手行动或下一轮发牌。
5. 轮次进入 `between` 后，`advanceStreet()` 发公共牌，或者触发 `settle()`。
6. 结算按每个池的参与资格比较最佳五张牌，并支付、退还和更新统计；重复结算受到保护。
7. 摊牌控制器显示每位未弃牌玩家的成牌，复盘控制器保存本手的独立输入。

`game` 是牌桌控制器持有的唯一进行中状态。规则计算位于纯引擎模块，不在按钮中重复实现。各模块在同一个浏览器内运行，不依赖登录、服务端或数据库。

## 异步任务的边界

对手计时器和“继续发牌”持有当前 `epoch`。下一手、重打或重置递增它，旧任务在继续之前核对编号。加速发牌也调用同一引擎的合法行动，不直接生成结算或修改赢家。

复盘优先使用 Web Worker，不阻塞牌桌操作。任务有独立编号；换手或重打终止旧 Worker，过期结果不会写入新手。无法创建 Worker 时按决策逐步计算，使用较少抽样，并在界面显示实际抽样次数。

## 三种“再来一次”

| 操作       | 底牌 / 公共牌序列    | 筹码和统计                             | 位置           |
| ---------- | -------------------- | -------------------------------------- | -------------- |
| 下一手     | 重新洗牌发牌         | 保留练习累计；破产玩家自动补充虚拟筹码 | 庄位顺时针移动 |
| 重打这手牌 | 恢复同一副牌的原序列 | 撤销本手旧结果，恢复本手开始时状态     | 保持原位置     |
| 重新练习   | 新练习               | 重置练习累计                           | 从新桌开始     |

重打基线由引擎保存为独立快照；连续重打不能叠加支付。电脑决策仍会重新运行，因此不同选择可能产生不同跟注或弃牌，不保证获得更多筹码。

## 页面与状态的观察

`window.noir.getState()` 提供公开牌桌状态，供本地诊断和浏览器工具读取。进行中不会返回对手隐藏底牌；摊牌仅公开有资格的未弃牌玩家。

`document.modelContext` 可用时会注册读取牌桌、执行玩家行动、下一手和同手重打工具。执行工具与点击按钮共用合法性检查。

## 测试环境

`vite --mode test` 的开发插件把 `tests/fixtures/table-fixtures.js` 注入牌桌控制器，提供可控的河牌、多人全下与分池场景。插件只在测试开发服务生效，生产构建没有 `window.qa` 或强制发牌入口。测试场景仍调用真实引擎、渲染和事件处理。

`dist/` 由构建生成，不提交到源码仓库。源码、配置、测试和文档才是迭代入口。
