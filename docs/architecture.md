# 架构与状态流

## 一次行动如何发生

1. `index.html` 加载 `src/main.js`，引入样式和 `table-controller.js`。
2. 牌桌按钮调用 `heroAction()`，引擎通过 `legalActions()` 和 `act()` 校验轮次、金额、加注权及筹码。
3. `act()` 在修改状态之前记录玩家决策快照，包含公开风格、情绪类别和行动权状态。对手隐藏底牌、剩余牌堆和未来结果不会进入玩家快照。
4. `render()` 根据引擎状态刷新筹码、牌面、位置、操作和动态；`schedule()` 安排对手行动或下一轮发牌。
5. 轮次进入 `between` 后，`advanceStreet()` 发公共牌，或者触发 `settle()`。
6. 结算按每个池的参与资格比较最佳五张牌，并支付、退还和更新统计；重复结算受到保护。
7. 摊牌控制器显示每位未弃牌玩家的成牌，复盘控制器保存本手的独立输入。玩家分析与对手执行解释各自使用隔离的数据。

`game` 是牌桌控制器持有的唯一进行中状态。规则计算位于纯引擎模块，不在按钮中重复实现。各模块在同一个浏览器内运行，不依赖登录、服务端或数据库。

每位玩家的 `lastAction` 保存已执行动作的公开文案、发生轮次及当时累计下注。当前轮次的 `action`、`bet` 仍按规则清理；结算展示读取保留快照，跟注金额是本次补入，加注和全下金额是动作发生时该轮累计投入。退还未被跟注筹码不会改写原动作，赢家领取筹码也不会把已全下改成其他动作。开始新手清空快照并记录新盲注；重打恢复原手盲注后、尚未行动的基线。查看底牌和练习补牌均不会改写快照。

## 本地选项与新练习

首次进入默认 6 人、标准难度、均衡对手、轻微情绪模拟、开启提示、关闭声音。`ui/preferences.js` 校验并恢复 `noir-table-v1` 中的人数和难度，在第一手发牌前建立对应人数的新桌；选择人数时立即保存意向，本桌仍在下一手切换。

对手配置继续使用 `noir-opponents-v1`，保留所有八个席位及情绪强度；减少人数不会删除暂未入座的风格。声音和提示继续使用 `noir-sound`、`noir-hints`，兼容既有选择。风格需点击保存，关闭未保存的对话框会舍弃草稿。

完整刷新或再次进入会恢复选项并开启新练习；底牌、公共牌、筹码、历史、统计和私有执行记录不会存入浏览器。重新练习保留选项；重打仍使用原手基线。损坏、无效或不可访问的存储回退默认值，无法写入存储时本次仍可正常操作。偏好只属于当前浏览器和站点来源，本地预览与在线站点各自保存。

## 异步任务的边界

对手计时器和“立刻发完”持有当前 `epoch`。下一手、重打或重置递增它，旧任务在继续之前核对编号。加速发牌也调用同一引擎的合法行动，不直接生成结算或修改赢家。

复盘优先使用 Web Worker，不阻塞牌桌操作。任务有独立编号；换手或重打终止旧 Worker，过期结果不会写入新手。无法创建 Worker 时按决策逐步计算，使用较少抽样，并在界面显示实际抽样次数。

## 三种“再来一次”

| 操作       | 底牌 / 公共牌序列    | 筹码和统计                             | 位置           |
| ---------- | -------------------- | -------------------------------------- | -------------- |
| 下一手     | 重新洗牌发牌         | 保留练习累计；破产玩家自动补充虚拟筹码 | 庄位顺时针移动 |
| 重打这手牌 | 恢复同一副牌的原序列 | 撤销本手旧结果，恢复本手开始时状态     | 保持原位置     |
| 重新练习   | 新练习               | 重置练习累计                           | 从新桌开始     |

重打基线由引擎保存为独立快照；连续重打不能叠加支付。电脑决策仍会重新运行，因此不同选择可能产生不同跟注或弃牌，不保证获得更多筹码。

## 页面与状态的观察

`window.noir.getState()` 提供公开牌桌状态，供本地诊断和浏览器工具读取。进行中不会返回对手隐藏底牌；摊牌自动公开未弃牌玩家。结算后眼睛按钮只切换对应座位的底牌显示，公开状态与牌桌显示一致。显示偏好不会改变引擎、筹码、统计或复盘输入；下一手、重打和重新练习都会清除它。

`document.modelContext` 可用时会注册读取牌桌、执行玩家行动、下一手和同手重打工具。执行工具与点击按钮共用合法性检查。

## 测试环境

`vite --mode test` 的开发插件把 `tests/fixtures/table-fixtures.js` 注入牌桌控制器，提供可控的河牌、多人全下与分池场景。插件只在测试开发服务生效，生产构建没有 `window.qa` 或强制发牌入口。测试场景仍调用真实引擎、渲染和事件处理。

`dist/` 由构建生成，不提交到源码仓库。源码、配置、测试和文档才是迭代入口。

本局动态按事件发生顺序展示：开始、盲注、行动、各轮公共牌、结算。引擎保留最新在前的日志数组，牌桌渲染时复制并倒序显示，避免修改重打基线或其他引擎状态。单列从上到下，多列每行从左到右再向下；屏幕宽度变化和反复渲染不会改变事件顺序。

## 策略与反事实模拟

正常计时行动及“立刻发完”都调用 `playBotTurn()`：先取得 `botDecision()` 的返回值与实际随机分支，再合法执行 `act()`，只记录一次已执行行为。单纯查询策略不写记录。本人底牌、判断扰动、范围门槛、分支抽样和尺度只保留于私有游戏状态，结算前不能进入公开诊断接口或复盘输入。重打基线包含空记录，重打会撤销上一尝试的轨迹。

`counterfactual.js` 根据玩家行动前的公开快照创建独立游戏，抽样未知牌；每个候选行动共享同一手抽样牌与后续策略种子。模拟用 `act()`、`advanceStreet()`、`botDecision()` 打完并结算，从而保留短全下、行动权、边池和退还规则。原游戏不被修改。后续判断为快速小样本均衡／公开风格策略，结论只在这些模型内成立，不能被称为 GTO。

Worker 只收到玩家决策与结算展示字段；私有对手执行记录仅用于独立的对手面板，不能进入玩家的模型计算。
