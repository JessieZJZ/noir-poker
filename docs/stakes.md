# 筹码与盲注配置

所有端默认小盲 100、大盲 200、起始筹码 20000（100 BB）。小盲只支持 25 的正整数倍且最多 50K；筹码面额等于小盲。设置中的大盲自动为小盲两倍，起始筹码自动为 100BB。

在“牌桌与声音”中点击小盲后输入完整数字。0、负数、小数、K/M 写法、不是 25 的倍数或超出 50K 均显示红色提示，不改变当前手或已保存配置。合法输入即时更新待生效设置，并显示“下一手起始盲注xx/xx·筹码恢复为xx，统计重新开始”。更改不会打断当前手、复盘或重打；点击下一手后重开第一手、恢复全部筹码、清零整场统计。重打仍使用原手尺度与原始发牌，同时保留待生效设置。改回当前尺度会取消待生效重置。完整刷新按本地保存的设置开始新练习。

```js
const game = newGame(5, { smallBlind: 300, bigBlind: 600 });
// 自动派生 chipUnit = 300，startingStack = 60000
startHand(game);
configureStakes(game, { smallBlind: 25, bigBlind: 75 });
// 清除原手、筹码投入与统计，回到 idle；所有人恢复 7500 筹码
startHand(game);
```

配置在新建牌局时复制并校验。兼容传入派生字段，但它们必须等于小盲／100 BB，矛盾配置会在改变状态之前被拒绝。破产补入也使用 100 BB。

Web/App 的 `window.noir.requestSmallBlind('300')` 与微信适配器的 `requestSmallBlind` 共用严格输入校验，派生并保存 300/600、60K 的下一手设置；`requestStakes` 接受完整的同等派生配置。微信的 `setPreference('stakes', value)` 也使用待生效路径。应用新尺度时取消原手的机器人、复盘、提示及动画工作，旧结果不能写回新练习。

保留原有底层 `window.noir.setStakes({smallBlind, bigBlind})`／微信 `setStakes` 的即时重开能力，供内部调用和固定尺度验证；设置界面使用 `requestSmallBlind`。引擎仍支持大盲为小盲的更高整数倍，便于其他尺度扩展。引擎 `configureStakes` 本身不管理平台计时器，调用方负责取消异步工作。

每手状态、行动前公开快照与机器人视角记录实际盲注、面额。最低下注、完整加注、短全下、不重开的加注权、底池快捷项、退款和按钮顺序的奇数筹码分配使用这些值。机器人范围、情绪阈值、思考时间和复盘 BB 换算使用该手实际大盲。

普通重打恢复同一手的配置、发牌与统计。仅保存待生效盲注时保留重打入口；下一手实际应用并重开整场后，才移除旧手的重打入口。未来周期涨盲需显式区分变更整场配置与下一手等级推进；当前尚未启用涨盲模式。

筹码与盲注金额显示统一用 K/M，并保留整数筹码精度，例如 20000 → 20K，1100 → 1.1K，1000100 → 1.0001M。牌桌行动、动态记录、复盘、统计及设置提示共用金额格式；金额紧贴“至”时也正常转换。年份、手数和百分比不转换。各语言使用本地小数点，账本仍为整数，编辑框在输入时显示完整数字。

旧规则边界测试显式使用 25/50、5000、25 的历史配置；新回归覆盖 100/200、25/75、500/1000 与 50K/100K，检查守恒、短全下、奇数分池、退款及变更后的整场重置。Web 与微信回归另检查输入边界、连续重打保留旧尺度、下一手应用与保存配置。

微信开发者工具的实际换盲回归使用 `tests/wechat/stakes.mjs`。连接已启动的目标工程自动化端口后，传入 WebSocket 地址及报告目录：

```sh
node tests/wechat/stakes.mjs "$NOIR_WECHAT_AUTOMATION_URL" .artifacts/wechat-stakes
```

该脚本通过实际设置控件与控制器行动验证输入红色提示、待生效配置持久化、重打原手、下一手重开、结算守恒和旧异步任务取消。结束时恢复默认尺度，保留其他偏好；只在专用测试工程中运行。
