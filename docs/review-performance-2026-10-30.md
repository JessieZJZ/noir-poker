# 复盘首次打开性能：2026-10-30

首次复盘保留完整的当前公开信息分析，将整手候选推演留给离线审查。每种范围 600 次权益抽样、河牌单挑枚举、牌型／听牌、价格／分池、完整公开行动线与公开策略解释保持原算法。真实对局机器人没有改用简化策略。

原先最多 7 个候选 × 2 种范围 × 40 手后续牌局，每个模拟行动又调用机器人的范围、权益与策略分析。仅减少每次权益抽样，仍会反复构造范围和推演。交互版现在直接跳过这一层，不再用整局推演寻找补充改进路线；这会损失一部分路线比较能力，不声称与完整分析等精度。完整 `analyzeDecision()` 默认行为仍保留，便于离线核查。

Web/App 最多两个 Worker 并行处理独立决策；微信使用单 Worker。缓存步骤不重新派工，关闭／切后台／换手／重打／重置会终止旧任务，故障回退保留已完成步骤。翻前 169 类百分位改为预计算查表，纯范围权重按完整公开上下文缓存；这两项保持原数值，不缓存机器人动作或随机结果。

## 相同输入的计算对照

以改动前 `1ce707e` 的本地源码归档为基线，对现有 11 个行动前测试快照运行 `node scripts/benchmark-review.mjs /绝对路径/src/review/analysis.js`。覆盖翻前、翻后、弱牌入池、强成牌取值、全下与河牌，也包含没有完整续打元数据的旧记录。双方均保持原主分析精度，每个快照清空纯牌面缓存。

| 指标                     | 结果                             |
| ------------------------ | -------------------------------- |
| 11 个决策串行计算合计    | 30.553 秒 → 0.531 秒，减少约 98% |
| 主权益／价格指标逐项一致 | 11/11                            |
| 可能牌组逐项一致         | 11/11                            |
| 建议行动及尺度一致       | 11/11                            |

这是 Node CPU 基准，不是实体手机耗时；11 个样本的一致性不证明所有局面语义或精度等价。对手解释单独测量，没有再执行玩家整局候选推演。首次耗时与缓存重开分别记录，不能混报。

## 回归与证据边界

单元回归覆盖公开权重失效、1,326 组翻前组合等值、筹码与分池、无隐藏牌输入、候选推演开关、并行乱序／取消／故障与微信回退一致性。浏览器专项覆盖复盘正文、语言、缓存、历史、全下和界面点击。

快速结果填入曾使分析进度行消失，视角按钮上移约 42.6px，可能把点击落到决策卡片上。进度行移到视角按钮之后，Web/App 弹窗保持固定可用高度；新增真实 Worker 渐进渲染回归，检查完成前后的按钮位置与点击。

本地完整日志、原始失败、CPU profile、旧源码归档、A/B JSONL、DevTools 与安装版报告保存在 `.artifacts/review-performance-2026-10-30/`，不上传牌谱与截图。Xcode／Gradle 编译、资源核验、安装版 Appium、DevTools 和实体手机属于不同证据层；通过前四项不能代替小米 14 Pro 或实体 iOS 的首开速度验收。
