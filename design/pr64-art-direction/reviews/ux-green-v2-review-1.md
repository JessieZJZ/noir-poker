## GV2-01 · P1 · 1280×720桌面筹码与本人牌重叠、牌型被操作区覆盖

这是当前浏览器原型的实测，不是仅从源码猜测：

- `.felt-area`实际高410px。
- `.pot-chips`范围y=385.8–427.8；`.hero-cards`范围y=398.1–489.1，两者垂直重叠约29.7px。压力截图中筹码从本人底牌后方露出。
- `.hero-rank`范围y=540.1–555.1，而`.action-area`从y=534开始，牌型落入动作面板下方。

修改要求：桌面低高度也需要独立空间预算，重算底池/公共牌/筹码组与本人区域，不能固定publicY46%和heroY86%后只调桌高。可以减少牌组间无功能留白、将筹码和底池并排、降低装饰筹码堆高度；本人牌、筹码金额、牌型与主操作完整保留。最小垂直净距8px。再次验证1280×720和1194×834等低高宽屏。

## GV2-02 · P1 · 多个操作真实触摸区域不足48px

实测当前DOM矩形，阴影/金属边不能算点击区：

| 控件                 | 观测尺寸               | 尺寸来源                            |
| -------------------- | ---------------------- | ----------------------------------- |
| 移动设置齿轮         | 14×48                  | 320、360、393三个尺寸均一致         |
| 底池明细             | 约50×16（393约55×16）  | 三个手机尺寸                        |
| 短屏尺度入口         | 44×44                  | 320/360                             |
| 常规手机四个快捷尺度 | 约84×36                | 393×852                             |
| 牌力表               | 约54×25                | 393×852                             |
| 设置开关             | 44×44，视觉轨道约42×25 | 另测393设置页；已有扩大，尚未达到48 |
| 设置选择             | 104×44                 | 393语言/人数/难度/情绪              |
| 小盲输入             | 70×44                  | 393设置页                           |
| 返回牌桌链接         | 约65×38                | 393设置页                           |
| 重新开局             | 60×32                  | 手机/桌面统计区域                   |

修改要求：手机/触控平板均按48×48真实命中设计；可以把底池整体做成一个48px高的详情入口，把开关/选择的实际按钮扩到48，而不是全局把所有字体放大。齿轮按钮增加最小宽48并保留『设置』可访问名称。短屏可调导航文案/留白保证一行装下。

姓名/金额实测均不小于11px，风格/最近行动不小于10px，现有这一点符合本轮要求。主行动按钮也有50px高，继续保留。

## GV2-03 · P2 · 短屏尺度展开会完整盖住本人牌与筹码

320×568展开快捷尺度时，抽屉y≈322–451，盖住本人底牌、金额与身份。下注时最需要核对自己的牌，不适合把它放在抽屉背后。当前点击同一入口可收起，但文字/箭头没有明确变化。

建议：点击『尺度』后，让四个快捷值+关闭入口临时替换48px滑杆行；下方加注主按钮继续显示当前金额。选择后自动收起，退出时恢复滑杆。避免覆盖公共牌或本人牌。也可以使用其他不遮关键牌区的布局，但必须有明确关闭状态，主动作始终可达。

## GV2-04 · P2 · 桌面位置徽章换行改变玩家核心高度

1280×720和第一轮桌面9人图中，Owen的UTG+1换到姓名下一行，核心高约85.7px，其他人约67.5px；同一座位锚点不再代表相同可见中心，顶部两座不齐。

修改：位置徽章放独立稳定槽位，例如玩家名牌右上方，或预留统一一行，别让姓名+徽章挤在一行自然换行。所有玩家核心维持相同高度，姓名/风格/金额的行序稳定。手机现有徽章在上缘的方向可保留，但不能压住牌背。

## GV2-05 · P2 · C方案牌背变奶白色

C方案5/9人桌的对手牌背近似奶白正面，A/B为绿色。冷色卡面不应把未知底牌也变成正面质感。

源码根因：末尾`[data-art='green-v2'][data-theme='polar'] .card`覆盖了`.card.back`的绿色背景。建议限定`.card:not(.back)`，三方案牌背继续是绿色纹样；牌背/翻开正面不能仅依赖牌点是否刚好被遮挡来区分。

## 第一轮其他观察

- 当前393×852的5人和9人图没有看到姓名/金额被桌沿或牌组遮住，主操作底部在手势区上方。房间背景有明显游戏质感，但仍让位给牌面和金额。
- 320×568的九人姓名、金额、公共牌和主操作均在视口内，没有横向滚动；公共牌32px宽的最短屏变体依然保留清楚的16px点数。其完整5–9人数和多状态尚未验证，不能由九人单图推断全部通过。
- 复盘/设置的文字主体有足够深色承托；顶部环境可见，没有直接穿过关键正文。复盘仍然区分当时信息与最终输赢。
- 不要求为所有尺寸强行加入荷官。大桌可以增加牌堆/荷官发牌锚点，短屏保留房间纵深与桌面实物感已足以承载方向。
- 三主题共享几何问题应一次修复，再逐主题看新图；不要把一套修复的截图当作三套已通过。

## 下一轮要求与边界
