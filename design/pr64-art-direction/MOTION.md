# NOIR Poker 动效与声音样片

初稿基线：PR #64 · `03d785e314758841a865ce31e299d244c91fb5b6`；最终工作树基线为 `aed7c68a84485af4399c9f38a5b84856e576749c`。八个声音、音频文件和共享特效源码逐字节等价，证据见 `base-equivalence.json`。每套方案分别提供桌面与 iOS 参考视口的32秒视频。它们是设计原型的逐帧浏览器渲染，不是已安装 App 或微信 DevTools 录屏。片段用于比较 UI 反馈，不作为一手连续合法牌局的回放。

用户提供的 `effects-comparison.mp4` 已实际查看。新方案保留强牌紫色边缘光、四类情绪头像环与图标、补码数字、金冠与双侧撒花、出局灰卡的现有语义，并沿用共享的运动路径、时长与声音。

## 音源与混音

前景由当前 `src/ui/sound-cues.js` 的 `soundSamples` 及 `src/ui/ceremony-sounds.js` 的 `ceremonySamples` / `ceremonyWav` 输出，未换音色。筹码声仍为用户已批准的510ms原视频节奏。`source-chip.wav` 保留原PCM；仪式音源保留原22050Hz WAV，视频混音线性重采样为44100Hz。AAC仅用于视频兼容性，不替代生产PCM。

桌面使用 `public/audio/background-music.m4a`，移动使用 `public/audio/background-music-mobile.m4a`。背景单位增益，2.4秒渐入；动作期间不改变背景音量。前景单位增益，重叠混音采用项目共用 `limitSoundMix`。`media-audit.json` 记录浮点混音峰值、AAC解码样本峰值与削波检查；这些是文件信号测量，不是实体扬声器听感或声压测量。

## 跨端还原

采用相同素材、节拍、持续时长、路径端点与触发语义。移动仅按可用区域转换位移距离，并保留安全区和微信胶囊。iOS参考视口393×852；H.264 4:2:0要求偶数宽，因此导出右侧补1像素为394×852，不缩放界面。

生产实现继续遵守 PR #64 的后台暂停、换手/重打/重置取消旧回调、独立音乐与音效开关，以及减少动态偏好。强牌提示不代表必胜；情绪环只描述训练模型的当前情绪，不揭露底牌。

`media-audit.json` 保存每段轨道、尺寸、32秒时长、768帧、SHA256、实际加载源SHA、音频源SHA、精确声音触发点、渲染耗时和共享效果来源。浏览器渲染与实际设备验收分开报告。
