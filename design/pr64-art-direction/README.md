**建议选 A。** 它保留现有用户对 NOIR 的识别，同时让桌布、卡牌、筹码与角色形成完整空间。B 的仪式感最强；C 的行动信号最明确。三套均是同一产品的信息架构与能力，不按主题改变规则或增加登录、购买、现金筹码等流程。

### A：翡翠私享牌室

牌桌是画面中唯一有明显材质与接触阴影的区域。桌边低亮，中央稍亮，暖白卡牌保持最高明度。薄荷色集中在主行动和本人回合，角色信息使用更暗、更实的底板。背景不持续飘粒子，普通胜局也不触发冠军庆典。

设置、记录和复盘延续同一绿黑底色，但显著减弱材质；复盘先给结论和依据，再给练习重点。入口是已经准备好的牌桌，无需增加大厅。手机依靠竖向椭圆和底部动作建立沉浸，桌面依靠横向桌面与右侧观察栏建立空间。

### B：黑金沙龙

香槟金只落在桌沿、局部边线与主要动作，桌布保持炭黑；避免整个画面变黄。卡牌为暖象牙白，筹码有金属边但保留面额。标题通过本地 Noto 的轻字重和字距形成气质，不依赖某个系统才有的宋体。

记录页像简洁的局账；复盘和设置像沙龙里的阅读桌，去掉牌桌大面积纹理，保留细线与暖色留白。手机不扩大金色按钮到遮蔽牌面的程度；冠军保留皇冠与撒花，但降低粒子饱和度，仍清楚表达庆祝。

### C：极夜竞技

冷色边线和轻网格建立空间，不用大面积霓虹。人物信息框更规整，头像有较小圆角，当前行动通过文字、边线与稳定按钮一起表达。局部切角只用于风格卡片与确认层，不切割需要完整阅读的正文。

复盘使用清楚的时间线和分栏；记录数字对齐、状态直接；设置沿用 6px 面板轮廓。手机将拥挤桌的五张公共牌排为居中 3+2，优先留住人物和金额的可读性。

## 统一还原的约束

1. **一份语义 token。** 主题按背景、面板、桌布、主行动、文本、错误、估计、成功与分隔线定义。原型的 `manifest.mjs` 和 `screen.css` 是此轮准确目标；B 的桌布最终值为 `#252620`。
2. **本地字形。** 金额和西文使用包内 Manrope，中文用包内 Noto Sans SC；牌面与图标在生产实现时复用已有向量路径。不得用系统 emoji 替代黑桃、皇冠或情绪图标。新增中文需重新生成现有字体子集；国际化继续覆盖 Web/App 全部 11 语言，微信只中文。
3. **一份资产。** 保留现有原创角色、logo、配乐与已批准筹码 PCM；纹理优先用轻量程序图层或包内压缩纹理。各端不得临时下载远程图片或字体。微信受主包预算限制，不能直接把整张大图塞入主包。
4. **一份几何与规则。** 真实实现继续使用 `src/ui/seat-geometry.js`、`compact-table-layout.js` 与 `rail-layout.js`。规则、合法行动、补码/结算仍来自现有引擎；设计预览没有实现第二套扑克规则。
5. **同一交互语义。** 弃牌、跟注、加注固定顺序；数字使用等宽数字特性。只有当前行动者高亮；BTN 唯一，其下一顺时针为 SB、BB。历史只读，不暴露影响当前局的控件。
6. **长页完整。** 首屏截图用于比较第一眼；完整长图用于检查页面所有内容。长图不把系统手势条叠在正文中；手机原型通过滚动查看内容。
7. **音效、配乐、振动独立。** 保留用户偏好，不替换已批准声音。后台、下一手、重打、重置、方向阻塞时的取消/暂停规则必须与 PR64 一致。
8. **降低动态。** 开启减少动态时取消飞行、翻转、缩放、撒花和闪光，仅保留静态轮廓、文字和结果；声音开关独立。不得用仅颜色区分行动、花色、情绪和复盘结论。

## AI UI 与 UX 审阅及迭代

审阅由独立 UI/游戏美术、UX 专业角色 agent 完成；动效由另一名 UI 动效 agent 制作。它们是 AI 审阅，不是真人用户研究或真人设计师签字。

第一轮逐个方案查看桌面与 iOS 的多人桌、复盘、设置和风格页，提出并修正：双行动者、重复 BTN、系统字体依赖、九人桌小字、B 桌布偏黄、C 圆角不统一、保存语义、底池示例资格、对手私牌与公开牌面、只读历史入口和长图安全区。第二轮复看并补强牌、情绪、补码、冠军、出局、边池和对手复盘，统一状态金额与“下一局”语义。
